# Mesa Tica verification

Results of the repository-owned checks against [context/acceptance.md](../context/acceptance.md). Automated checks
are not real-user validation, and local loopback runs are not network, load or hosted measurements.

## Environment and commands

- Recorded run: 2026-11-10T03:04Z on macOS (Darwin 27.0, Apple silicon), Node.js 24.5.0, Playwright 1.63.0 with
  Chromium revision 1243 (headless), emulated Pixel 7 ("phone") and Desktop Chrome ("desktop") profiles.
- `npm test` → **60 passed, 0 failed** (node:test: 15 unit + 45 API/process checks, ~3.2 s).
- `npm run test:browser` → **37 passed, 0 failed** (~25 s, 4 workers).
- The browser suite had also passed in full twice in a row before the final documentation changes (37/37 each);
  no flaky or contradictory outcome has been observed so far. During development, failures were test-authoring
  mistakes (ambiguous locators, a hidden button counted, a default parameter hiding an anonymous request) and were
  fixed in the tests; no product behavior was loosened to make a test pass.
- Isolation: each browser test and each API test file starts the real app handler on a fresh data directory with
  noninteractive setup (generated staff passwords read from the credentials file) and a test clock set to Tuesday
  2026-11-10 12:00 Costa Rica. Assertions read durable state (order/attempt/status-change counts, stored totals and
  statuses) from that test's SQLite file. The RUN/SETUP checks start the production entry point `src/server.js` as a
  separate process with the system clock.
- Manual check: `npm run setup` (twice) and `npm start` with defaults on 2026-11-09 ~21:02 Costa Rica served the
  menu with "Ordering is closed. Opens Tuesday, November 10 at 10:00 AM (Costa Rica time)." and `/staff` (HTTP 200).

Test files: unit `test/unit/*.test.js`; API `test/api/checkout.test.js`, `test/api/staff-and-tracking.test.js`,
`test/api/request-validation.test.js`, `test/api/setup-and-restart.test.js`; browser `e2e/*.spec.js`.
